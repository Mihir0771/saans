# AGENTS.md — Rules for every agent working on Saans

Read `docs/SPEC.md` first. It is the source of truth. If something is ambiguous, pick the safest reasonable reading, write a one-paragraph ADR in `docs/ADR/`, and continue.

## Mission

Ship **Saans**, the Challenge 6 Urban Air Quality Assistant, as a verified, deployed, accessible, secure app. Quality and honesty beat feature count.

## Hard rules

1. **Single branch `main`.** No other branches or worktrees pushed. Small commits with clear messages.
2. **Repo < 10 MB.** Never commit `node_modules`, `.next`, videos, large images, datasets, or `.env*` (except `.env.example`). Run `npm run guard` before each push.
3. **No secrets in code, logs, prompts, tests, screenshots, or git history.** If one leaks, stop and tell the human immediately.
4. **No invented facts.** Every parameter in `src/engine/params.ts` needs a real source in `docs/ASSUMPTIONS.md` (title, URL, what value was taken, confidence A/B/C). If you can't find one, label it `C` (heuristic) — never fabricate a citation, study, statistic, or URL.
5. **Engine computes, Gemini narrates, server verifies.** The LLM never produces numbers. Numbers appear only via `{{fact:id}}` slots filled by the server. Never weaken `guard.ts`.
6. **Safety rules in SPEC §6.5 are hard blocks** in code, prompts and tests. No ozone generators; never advise sealing a room with indoor combustion; no masks for children < 2; no medical diagnosis.
7. **Report only real results.** Test counts, coverage, Lighthouse and axe numbers in README/blog must be copied from `VERIFICATION_REPORT.md` generated by `npm run verify`. If a check fails, say so and fix it — do not edit the report or the check to pass.
8. **Label non-live data** (demo, simulation, fixture, stale, user-calibrated) on screen every time.
9. **Privacy by default:** profile stays in `localStorage`; coarse location only; no analytics that identify people.
10. **Don't copy other people's code.** Study ideas only; write original code. Include attribution for data sources (CAMS/Open-Meteo) in the UI.

## Code standards

- TypeScript `strict`, no `any`, no non-null `!` without a comment. Zod at every boundary.
- Engine is pure (no I/O, no Date.now, no randomness unless seeded). Inject time & params.
- ESLint complexity ≤ 10, file ≤ 250 lines, function ≤ 50 lines. Prefer small, named, tested functions.
- No hard-coded UI strings: use `src/i18n/{en,hi}.json`. Hindi must be natural Devanagari, reviewed for tone (calm, practical).
- No dead code, no commented-out blocks, no `console.log` in app code.
- Accessibility is a feature: semantic HTML, labels, focus states, contrast, reduced motion, colour never the only signal.

## Workflow for every task

1. Produce/refresh the **Task List** and **Implementation Plan** artifacts before coding.
2. **Tests first** for engine and guard logic (known-answer + property tests).
3. Implement the smallest slice that works end to end; run lint, typecheck and tests.
4. Verify UI in the browser agent at 360 px and 1280 px, `en` and `hi`, light and dark; capture a recording/screenshot artifact.
5. Update docs (`ASSUMPTIONS`, `SECURITY`, `ACCESSIBILITY`, README) when behaviour changes.
6. End each task with a short **Walkthrough** artifact: what changed, what was verified (real command output), what is left.

## Parallel-agent protocol

- One agent owns one area at a time: **Engine**, **Data/API**, **AI**, **UI**, **QA/Security/A11y**, **Docs/Deploy**. Don't edit another area's files without a note in the plan.
- Shared contracts live in `src/engine/schema.ts` (Zod). Change them only with an ADR and update all consumers + tests in the same commit.
- Merge conflicts: prefer the owner's version; re-run the full test suite after resolving.

## Definition of done (every PR-sized change)

Typecheck ✓ · lint ✓ · tests ✓ · a11y check on touched screens ✓ · no new dependency without justification ✓ · docs updated ✓ · `npm run guard` ✓.
